## Act 1 · Hook

### 01 · ปัญหา: คนทำไม่ได้เงิน

สวัสดีครับ ก่อนจะเล่าว่าเราสร้างอะไร ขอเกริ่นปัญหาก่อนครับ

ทุกวันนี้มังงะแปลไทยโดนดูดไปลงเว็บเถื่อนเต็มไปหมด คนแปลกับคนวาดไม่ได้เงินสักบาท ส่วนเว็บถูกกฎหมายที่มีอยู่ก็มีปัญหา — ถ้าตอนไหนโดนแจ้งลบ เงินที่เก็บจากคนซื้อมาแล้วจะทำยังไง? ใครได้คืนบ้าง? ส่วนใหญ่ไม่มีคำตอบครับ เงินค้าง คนซื้อโวย คนทำเสียขวัญ

นั่นคือปัญหาสองข้อที่โปรเจกต์นี้จะแก้ — หนึ่ง ทำให้คนจ่ายเงินถึงคนทำจริง สอง ทำให้ตอนลบแล้วเงินย้อนกลับอัตโนมัติทุกคน

### 02 · DOOTOON คำตอบของเรา

คำตอบของพวกเราชื่อ DOOTOON — อ่านว่าดูตูน เป็นเว็บอ่านมังงะกับนิยายภาษาไทยครับ

โฟลวทั้งระบบอยู่บรรทัดกลางจอ — คนอ่านเปิดตอนฟรีได้เลยไม่ต้องสมัคร ถูกใจค่อยจ่าย เงินวิ่งไปหาคนวาดกับคนเขียนจริง ๆ แล้วถ้าตอนไหนมีปัญหา แอดมินกดลบปุ๊บ ระบบคืนเงินให้คนซื้ออัตโนมัติทุกคน

เว็บรันอยู่จริงที่ dootoon.store นะครับ ไม่ใช่ mock ข้างหลังเป็น Go เก้า services บน Kubernetes มี pipeline deploy อัตโนมัติ แล้ว load test วัดจริง p95 ได้สองร้อยห้าสิบเอ็ดมิลลิวินาที error ศูนย์เปอร์เซ็นต์

## Act 2 · Context

### 03 · Why this exists

ทำไมต้องมีเว็บนี้? เพราะมีสามฝ่ายที่เจ็บอยู่ครับ

คนอ่านอยากอ่านมังงะกับนิยายไทยที่เดียว เปิดฟรีได้เลย จ่ายเฉพาะตอนที่อยากอ่านจริง ไม่ต้องสมัครก่อนถึงจะเห็นของ

คนทำ — ทีมแปลกับทีมวาด — อยากแบ่งรายได้ตามเปอร์เซ็นต์อัตโนมัติ คนแปลเจ็ดสิบ คนคลีนภาพสามสิบ ไม่ต้องทวงกันเองปลายเดือน

ส่วนแพลตฟอร์ม กลัวที่สุดคือตอนมีปัญหาแล้วเงินค้าง ถ้าตอนไหนโดนแจ้งลบแล้วไม่คืนเงินคนซื้อ มันคือคดีความครับ ระบบนี้เลยออกแบบให้ลบปุ๊บคืนปั๊บทั้งสาย

### 04 · Constraints we designed around

ก่อนเขียนโค้ด เราตั้งข้อจำกัดไว้สามข้อ แล้วออกแบบทุกอย่างให้อยู่ในกรอบนี้ครับ

ข้อหนึ่ง — เงินห้ามพัง หักเงิน ให้สิทธิ์ แบ่งรายได้ ต้องสำเร็จพร้อมกันหรือย้อนหมด ไม่มีครึ่ง ๆ กลาง ๆ ไม่มีใครจ่ายแล้วอ่านไม่ได้

ข้อสอง — รูปคือ 95% ของทราฟฟิก รูปห้ามวิ่งผ่านเซิร์ฟเวอร์ ไม่งั้นค่า bandwidth กลืนกำไรหมด ข้อนี้ตัดสินสถาปัตยกรรมทั้งระบบ

ข้อสาม — งบนักศึกษา demo ต้องอยู่ใน Azure credit เดือนละยี่สิบกว่าเหรียญ เปิดเฉพาะตอนซ้อม ปิดทันทีหลังจบ

## Act 3 · Journey

### 05 · How we got here

สี่สัปดาห์ครับ สัปดาห์แรกเขียนสเปก — requirement สถาปัตยกรรม schema ฐานข้อมูล สัปดาห์สองเขียน core services แบบ local-first ระบบเงิน ด่านสิทธิ์ test ครบ สัปดาห์สามทำ pipeline กับ deploy แบบไม่มี downtime สัปดาห์สี่ขึ้น cloud จริง แล้ววัดผลด้วย load test

หลักการคือทุกสัปดาห์มีของรันได้ ไม่เขียนสเปกเดือนนึงแล้วค่อยโค้ดครับ

### 06 · Key decisions along the way

ระหว่างทางตัดสินใจใหญ่ ๆ หกข้อครับ

ที่เก็บไว้ — REST ธรรมดาเพราะดีบักด้วย curl ได้ สมุดบัญชีใน Postgres เพราะเงินต้อง ACID R2 เพราะ egress ฟรี Envoy เพราะของเก่าหมดอายุแล้ว

ที่ตัดทิ้ง — Redis เพราะวัดแล้ว Postgres เร็วพอ Queue เพราะยังไม่มีคนใช้ gRPC เพราะเกินความจำเป็น

หลักการเดียวคือวัดก่อนใส่ มีตัวเลขค่อยเพิ่มของ Act 5 มีหลักฐานให้ดูทุกข้อครับ

## Act 4 · Solution

### 07 · One request travels where

มาดู request หนึ่งครั้งวิ่งไปไหนบ้างครับ อ่านรูปจากบนลงล่างสามชั้น

ชั้นบนคือทางเข้า เบราว์เซอร์ยิงเข้า Cloudflare ที่ช่วยจำชื่อเว็บ กันยิงถล่ม เก็บสำเนารูป แล้วเข้า Envoy gateway แบบเข้ารหัส แยกสองทางไปเว็บกับ API

ชั้นกลางคือหัวใจ กล่องแดง reader มีกฎเหล็กว่าจะไม่เสิร์ฟเนื้อหาให้ใคร ถ้ายังไม่ได้ถามสามเจ้าว่าคนนี้อ่านได้ไหม ได้แก่ catalog ว่าตอนนี้ปกติไหม commerce ว่าจ่ายแล้วหรือยัง identity ว่าคนนี้เป็นใคร เหมือนยามที่โทรถามสามบ้านก่อนปล่อยรถเข้าครับ

ชั้นล่างคือที่เก็บของ Postgres ที่เดียวที่ทุก service ฝากของไว้ กับ R2 เก็บรูป เส้นประแปลว่า Go แค่เซ็น URL ให้ แล้วเบราว์เซอร์ไปโหลดรูปเอง รูปไม่วิ่งผ่าน Go เลย

### 08 · Web: BFF pattern

ฝั่งเว็บใช้ pattern ที่เรียกว่า BFF — หลังบ้านที่ทำมาเพื่อหน้าบ้านโดยเฉพาะครับ โค้ดในเบราว์เซอร์ห้ามคุยกับ Go ตรง ๆ มันคุยแค่ `/api/` ของ Next.js เอง แล้วเซิร์ฟเวอร์ค่อยคุยกับ Go ต่อ

ทำไมต้องอ้อม? หนึ่งคือเบราว์เซอร์จะได้ไม่เห็น URL กับ secret หลังบ้าน สองคือเซิร์ฟเวอร์ประสานหลายเจ้าได้ในรอบเดียว ถ้าให้เบราว์เซอร์ทำเองสามสี่รอบทั้งช้าทั้งรั่ว

รวมยี่สิบ routes ครับ ตั้งแต่เงิน กระเป๋า แคตตาล็อก คอมเมนต์ ถึง auth

### 09 · Backend: 9 services

หลังบ้านเป็น Go เก้า services คุยกันด้วย REST ธรรมดา Go คือภาษาที่เร็ว กินแรมน้อย ส่วน microservices คือแยกโปรแกรมเป็นก้อนเล็ก ๆ ก้อนละหน้าที่ พังก้อนไหนแก้ก้อนนั้น

ไล่เร็ว ๆ — identity ดูคน catalog ดูของ commerce ดูเงิน reader ดูการอ่าน moderation ดูการแบน community ดูคอมเมนต์ library ดูตำแหน่งอ่าน media ดูรูป gateway เป็นประตูรับแขก

ทุกตัวเหมือนกันสามอย่าง — ไม่มี memory ในตัว มี health check สองเส้น แล้วแปะ trace อัตโนมัติทุกครั้งที่เรียกเพื่อน

### 10 · Money flow

รูปบนคือเติมเหรียญครับ กดซื้อแล้ววิ่งไป Stripe จ่ายเป็นบาท เราไม่เก็บเลขบัตรเองเพื่อความปลอดภัย

มีสองทางกันพลาด ทางหลักคือ webhook — Stripe ยิงมาบอกว่าจ่ายแล้ว เราตรวจลายเซ็นก่อนค่อยเติม ถ้าพังตอบห้าร้อยให้มันยิงซ้ำเอง ทางสำรองคือตอนผู้ใช้กลับมาหน้า wallet เราถาม Stripe ว่าจ่ายจริงไหม กันเคส webhook หล่น ทั้งสองทางใช้คีย์กันซ้ำชุดเดียวกัน เติมซ้ำไม่มีเบิ้ล

รูปล่างคือเปิดตอนอ่าน เซิร์ฟเวอร์ sync เรื่องลง catalog ก่อน แล้วถาม gateway ว่าอ่านได้ไหม ได้รหัสอะไรมาก็ map เป็นหน้าจอ สองร้อยคืออ่าน สี่ศูนย์หนึ่งไปล็อกอิน สี่ศูนย์สองจ่ายตัง สี่หนึ่งศูนย์คือโดนลบไปแล้ว

กฎราคาคือสามตอนแรกกับตอนล่าสุดฟรี ที่เหลือมังงะสามสิบ นิยายยี่สิบครับ

### 11 · Purchase: 5 steps, one transaction

นี่คือฟังก์ชันสำคัญที่สุดครับ ซื้อหนึ่งครั้งเกิดห้าขั้นใน transaction เดียว — ต้องสำเร็จพร้อมกันหมดหรือย้อนหมด

ล็อกทุกคนเกี่ยวเรียงชื่อกัน deadlock กันซ้ำด้วย idempotency key หักโบนัสก่อนเสมอโดยโบนัสไม่ปัน creator ให้สิทธิ์อ่านถาวร แล้วแบ่งเงินหักสามสิบเปอร์เซ็นต์ก่อนที่เหลือหารตาม % ทีม

ตัวอย่างคือซื้อสี่สิบเหรียญ ทีมเจ็ดสิบสามสิบ แพลตฟอร์มได้สิบสอง คนเขียนสิบเก้า คนวาดแปดครับ โค้ดเต็มอยู่ Appendix A2

### 12 · Gates + takedown

ก่อนเสิร์ฟเนื้อหา reader ไล่ด่าน — โดนลบไหม ฟรีไหม เป็นแอดมินหรือทีมไหม เคยซื้อไหม ไม่ผ่านด่านไหน guest โดนไล่ไปล็อกอิน user โดนบอกให้จ่ายตัง ผ่านแล้วเซ็น URL ทีละหน้าให้สิบห้านาที token คือลายเซ็นดิจิทัลปลอมไม่ได้ถ้าไม่มี secret

ส่วน takedown คือฟีเจอร์ที่ภูมิใจที่สุดครับ ลบหนึ่งครั้งเงินย้อนทั้งสาย — ซ่อนตอน บล็อกรูป วนคืนเงินทุกคน เขียน audit log ทำไมต้องมี? เพราะถ้าลบแล้วเงินค้าง มันคือคดีความครับ ระบบนี้ลบปุ๊บเงินไหลย้อนปั๊บ รันซ้ำก็ไม่ย้อนเบิ้ลเพราะสมุดบัญชีเขียนเพิ่มอย่างเดียวไม่แก้ของเก่า

### 13 · Data + auth

ฐานข้อมูลเป็น Postgres ตัวเดียวแยกห้องตาม service ครับ ทำไมไม่แยก DB? เพราะซื้อตอนต้องหักเงิน ให้สิทธิ์ แบ่งรายได้ใน transaction เดียวกัน ข้ามห้องได้แต่ข้ามบ้านไม่ได้

มียอดเงินไหม? ไม่มีคอลัมน์ยอดครับ นับจากผลรวมแถวบัญชีทุกครั้ง เลยไม่มีทางแย่งกันแก้ยอดเดียว มี migration เจ็ดไฟล์คุมโครงสร้างทั้งหมด

ฝั่งขวาคือ auth ใช้ better-auth ล็อกอินอีเมลกับ Google แล้ว sync ไป Go แบบ best-effort — Go ล่มก็สมัครได้ หลังจากนั้นคุยกับ Go ด้วย header บัตรประชาชนใบเล็ก ไม่ส่ง cookie ข้าม service ครับ

ก่อนจบ Act 4 มาดูภาพรวมทั้งระบบในหน้าเดียวครับ ไฟล์นี้เปิดแยกได้ด้วย

## Act 5 · Evidence

### 14 · Demo flow 7 steps

กลับมาที่คำสัญญาตอนต้นครับ เจ็ดขั้นนี้รันได้จบ มี test คุมตัวเดียว

guest อ่านฟรี สมัคร เติมร้อยโดย webhook ซ้ำนับครั้งเดียว ซื้อสี่สิบเงินแตกสามทาง อ่านได้ด้วยโฆษณาน้อยลง แอดมิน takedown แล้ว Alice ได้ร้อยคืนเต็ม creators เหลือศูนย์

กล่องเหลืองคือขั้นที่เงินวิ่ง เป็นสามขั้นที่ test จับตาดูใกล้สุดครับ

### 15 · Pipeline 4 stages

สายพานอัตโนมัติสี่ด่านครับ push ทีไรไหลแบบนี้ทุกครั้ง lint ตรวจโค้ด test รันบน Postgres จริงโดย coverage เงินต่ำกว่าแปดสิบตกทั้งสาย build สิบ images เฉพาะ master deploy ปัก SHA รอบละสิบเจ็ดนาที

ย้ายจาก GitLab มาเพราะ free tier หมดครับ รวมทุกอย่างไว้บิลเดียวจบ

### 16 · Inside Test

ซูมเข้าด่าน Test ครับ ข้างในมีสามก้อน — Postgres จริงไม่ใช่ mock unit test ทั้ง repo บวก integration test แล้วประตูกั้น coverage

ทำไมต้องแปดสิบ? เพราะ commerce คือตัวเงิน บั๊กตรงนี้คือเงินหาย ด่านนี้รันทุก branch แต่ build กับ deploy ไปต่อเฉพาะ master ครับ

### 17 · Cloud as built

รูปนี้คือของที่สร้างจริงทั้งหมด ยืนยันจาก state file แล้วครับ คนอ่านเข้า Cloudflare แล้วยิงเข้า VNet ก้อนเดียวที่แบ่งสองซอย ซอย AKS กับซอย Postgres ข้างล่างมี registry vault แล้ว R2 เก็บรูปแยก vendor

ไฟร์วอลล์มีแค่สองกฎ เปิดสี่สี่สามจากเน็ตกับห้าสี่สามสองจากซอย AKS เท่านั้น ของที่ตัดทิ้งอย่าง NAT กับ Bastion ประหยัดไปเดือนละหกสิบกว่าเหรียญครับ

### 18 · Numbers measured

สี่ตัวเลขข้างบนคือตัวชี้วัดครับ เบิร์นเดือนละสิบเจ็ดถึงยี่สิบสามเหรียญ egress รูปศูนย์เหรียญ p95 สองร้อยห้าสิบเอ็ดมิลลิวินาทีผ่านเป้าสามร้อย error ศูนย์จากหมื่นกว่า request พร้อม HPA ขยายจริง

ตรงกลางคือตัวเลขที่ตัดสินสถาปัตยกรรม ถ้าคนอ่านแสนครั้งต่อวัน รูปสี่สิบห้าเทราต่อเดือน วางบน Azure โดนห้าพันสี่ร้อยเหรียญ วางบน R2 โดนสิบเอ็ดเหรียญ ต่างกันห้าร้อยเท่า นี่คือเหตุผลข้อเดียวครับ

ฝั่งเก็บเงิน Stripe บัตรสามจุดหกห้าเปอร์เซ็นต์บวกสิบบาท เลยบังคับขั้นต่ำสามสิบห้าบาท ส่วน PromptPay หนึ่งจุดหกห้าเปอร์เซ็นต์ไม่มีขั้นต่ำคือทางหลักที่แนะนำ

### 19 · Trade-offs priced

ทุกการเลือกมีราคาที่จ่ายครับ R2 แลกกับการดูแลสอง vendor AKS แลกกับดูแล manifests เอง Postgres managed แลกกับแพงกว่านิดหน่อย Vault แลกกับ wiring เพิ่มชั้น OpenObserve แลกกับ ecosystem เล็ก Envoy แลกกับการเรียนของใหม่

ที่ตัดทิ้ง — Redis เพราะ Postgres เร็วศูนย์จุดหนึ่งมิลลิวินาทีแล้ว gRPC เพราะ REST พอ Queue เพราะไม่มี consumer pre-screen เพราะทำไม่ได้จริง อ่านไม่อั้นเพราะพังระบบแบ่งรายได้ครับ

## Appendix (เปิดเมื่อโดนถามลึก)

### A1 · Code: Stripe

ฝั่ง checkout สร้าง session จ่ายบาท ราคาคูณร้อยเพราะ Stripe นับสตางค์ ฝากคีย์กันซ้ำใน metadata ฝั่ง webhook ตรวจลายเซ็นก่อน เติมสองรอบแยกคีย์ พังตอบห้าร้อยให้ retry เองครับ

### A2 · Code: purchase + gates

ครึ่งบนคือซื้อตอนห้าขั้นใน transaction เดียวตามที่เล่า ครึ่งล่างคือด่านสิทธิ์เช็กจากถูกไปแพง ฟรี แอดมิน ทีม แล้วค่อยถาม commerce สังเกตว่าไม่มีบรรทัดไหนแตะ bytes รูปเลยครับ

### A3 · Code: takedown + Worker

ครึ่งบนคือ takedown สี่ขั้นตามลำดับ ต้องมีเหตุผลเสมอ ครึ่งล่างคือ Worker ยี่สิบบรรทัด ขาด หมดอายุ HMAC ผิดตอบ 403 หมด ผ่านถึงเสิร์ฟพร้อม cache หนึ่งชั่วโมงครับ
